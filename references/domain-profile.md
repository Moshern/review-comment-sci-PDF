# 本次领域配置

使用者只需输入研究方向即可开始；完整配置用于减少术语歧义和反复解释。配置属于本次任务或用户自己的资料文件，不需要修改 SKILL.md。

## 输入字段与默认行为

| 字段 | 用途 | 未提供时 |
|---|---|---|
| research_field | 学科、研究方向，可多选 | 从论文暂定并明确标记 |
| reader_background | 读者已有知识、希望补充的基础 | 按有一般研究训练的读者解释 |
| focus_questions | 关注的方法、结论或问题 | 覆盖论文核心主张 |
| terminology | 术语、缩写、首选译名及来源 | 从论文建立术语表 |
| background_sources | 用户资料、教材章节、专业规范或链接 | 不假定存在外部依据 |
| output_language | 输出语言 | 阅读中文；审稿中英双语 |
| target_venue | 期刊/会议和已有评审标准，审稿时使用 | 通用学术标准 |
| external_lookup | 是否允许外部检索及限制 | 遵循用户和宿主环境权限；不上传全文 |

这些是语义字段，不需要专用解析器。自然语言、Markdown 或 YAML 均可；运行中的智能体直接读取。

## 使用模板

把需要的字段写在提问中，或保存为自己工作目录的领域配置文件：

```yaml
research_field: ""
reader_background: ""
focus_questions: []
terminology: []
background_sources: []
output_language: ""
target_venue: ""
external_lookup: ""
```

空字符串和空列表表示“未提供”，不是待填补的领域事实。不要把此空模板当成已确认配置。

## 动态术语表

| 原文术语/缩写 | 首选译名 | 本文定义与适用语境 | 来源（页码或文献） | 状态 |
|---|---|---|---|---|

只收录理解本论文所需术语。首次出现写全称；同一缩写在不同学科存在多义时分别说明，不能沿用其他领域的含义。

- 本文定义决定对本文的解读；用户偏好决定表达方式。两者冲突时保留本文定义并解释差异。
- 用户资料是可参考背景，不自动成为已核验事实。外部标准需核对版本、适用对象和来源；链接无法访问时写明。
- 本文用语可能不规范，审稿时可指出有证据支持的差异，但不得静默改写作者的定义。
- 不确定译名保留原文。模型常识可用于标明为“背景解释”的教学内容，不可充当对作者作出负面判断的唯一依据。
- 跨学科论文分别记录领域概念和交叉关系；根据论文实际研究设计选检查项，而不是只按用户专业选择。

## 不同方向的示例（可选，非默认规则）

| 用户方向 | 可以提供的背景/术语 | 如何使用 |
|---|---|---|
| 教育学、定性研究 | 访谈、编码、研究者反思性；所采用的方法文献 | 解释材料到主题的推导，不要求训练曲线 |
| 数学、理论研究 | 本文定理符号、前提与证明背景 | 核查定义、假设和证明，不强求实验 |
| 材料科学、实验研究 | 样品制备、测量技术、指标定义 | 按本文主张核查实验条件和证据 |
| 计算方法研究 | 数据划分、基线、评价指标定义 | 区分方法性能与完整处理流程的性能 |

“支持不同领域”表示配置和流程不绑定学科，不代表模型掌握所有专业知识或已验证所有方向。专业依据不足时明确限制。
